Topic 14 Murphy, PML — §17.3.6 – 17.3.8 Kernel machines

One kernel, different knobs, different losses

Topic 13 built a kernel SVM. Two questions are left. First, the SVM has a knob C that decides how much training mistakes matter. How do you set it without fooling yourself? Second, kernels also work for regression, predicting a number instead of a class. There are two classic ways to do it. They use the same kernel but a different loss, and the loss decides which training points the model has to remember.

① Pick C with cross-validation ② Kernel ridge vs SVM regression
①

Choosing C: trust held-out points, not training points

Big idea
Training error always says "bigger C"

C is the price of a training mistake. Raise it and the SVM bends its boundary to fix more mistakes, so training error (mostly) falls. That says nothing about new points. Some labels are noise, and a boundary that chases them will be wrong on fresh data.

The book's recipe · §17.3.6
5-fold cross-validation over a grid of C

Split the data into 5 groups. For each C, train on 4 groups and count mistakes on the 5th, rotating so every point is held out once. The C with the fewest held-out mistakes wins. C interacts with the kernel width γ, so the book searches both together.

The true boundary is the dashed wave. About 8% of the labels were flipped on purpose (drawn with a dark halo): no sensible classifier should get those right. Slide C from left to right and watch both error curves.

Try this
  1. Start at C = 0.03 and step right. Training error (grey) heads to 0. Where does the orange CV curve bottom out?
  2. At C = 1000, look at the dark-halo noise points. The boundary has grown little islands to claim them. Does that help on new data?
  3. Switch to Narrow γ = 5. Training error hits 0% at a much smaller C. Narrow bumps are flexible, so it takes less C to overfit. That is why C and γ are tuned together.
  4. Hit New sample a few times. The best C moves around. With 60 points, the CV estimate is noisy too.
Why a log scale for C?

Going from C = 1 to 2 changes the SVM about as much as going from 100 to 200: what matters is the ratio. So the grid is spaced by factors of ≈3 (0.03, 0.1, 0.3, 1, …), the standard choice.

Why not just use a separate test set?

You can, if you have plenty of data. With 60 points, holding out 20 leaves only 40 to train on, and a score from 20 points is very noisy. Cross-validation uses every point for both training and testing, just never at the same time.

②

Regression: kernel ridge vs SVM regression

§17.3.7 · Kernel ridge regression
Squared loss: α = (K + λI)⁻¹ y

Predict f(x) = Σn αn K(xn, x). Each miss costs (error)², and λ penalises wiggly curves. The answer is one linear solve, but it is dense: every αn is nonzero, so prediction needs every training point.

§17.3.8 · SVM regression
ε-insensitive loss: max(0, |error| − ε)

Same f(x), but misses smaller than ε are free: a tube of half-width ε around the curve. Points inside the tube get weight exactly 0. Only points on or outside it are support vectors, so the model is sparse. C caps how hard any one point can pull.

Both fits use the same RBF kernel with the same γ. Click the plot to add a point; click a point to remove it. The bar chart underneath shows each training point's weight, lined up under the point. Grey ticks mean the weight is exactly zero.

Try this
  1. Compare the two bar rows. Ridge: a bar under every point. SVR: grey ticks wherever a point sits inside the tube.
  2. Slide ε from 0 to 1. Support vectors drop from nearly all points to a handful. Past some width, the fit stops following the wave: sparsity is not free.
  3. Press Add an outlier. Which curve gets dragged further toward it? Now lower C to 0.3 and watch SVR shrug it off.
  4. Set ε = 0. Every point is now outside the (zero-width) tube, so SVR uses all of them, just like ridge.
How does SVR find β, and why are some exactly 0?

The SVR dual is: minimise ½ βᵀKβ − yᵀβ + ε Σ|βn| with −C ≤ βn ≤ C. The ε Σ|βn| term is an L1 penalty, the same thing that makes the lasso sparse. This page solves it one βn at a time: each update is a "soft threshold" that snaps βn to 0 whenever that point's error is under ε. (A constant 1 is added to K so the curve can shift up or down. It plays the role of the bias w₀.)

Have I seen kernel ridge before?

Yes: it is exactly the Gaussian process posterior mean from Topic 12, with λ in the role of the noise variance σy². Ridge gives the same curve but no error bars.

And for every knob: C, γ, λ and ε are all chosen the way part ① chose C. Make a grid, cross-validate, and pick the lowest held-out error. Never judge by training error alone.

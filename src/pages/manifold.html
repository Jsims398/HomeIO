Manifolds: when the data is curved

PCA finds the best flat subspace. Manifold learning assumes the data lie on a low-dimensional curved surface inside ℝᴰ and tries to recover coordinates along that surface. Three walkthroughs: ① what a manifold is, on a rolled-up curve, ② why real data like images should lie on one, ③ the general recipe most methods follow, and how it breaks.

A U-shaped manifold, by hand

Data walk around a "U": A = (0, 3) B = (0, 0) C = (2, 0) D = (2, 3), joined A → B → C → D by straight pieces.

  1. Dimensions. Each point has 2 numbers, so D = 2. But one number, the distance travelled along the U, pins down any point on it, so the intrinsic dimension is d = 1.
  2. Chart (intrinsic coordinate). Arc length from A: t_A = 0, t_B = 3, t_C = 3 + 2 = 5, t_D = 5 + 3 = 8.
  3. Local distances agree. ‖A − B‖ = 3 and the path A → B is also 3. Neighbours on a straight piece: Euclidean = along the manifold.
  4. Far distances don't. ‖A − D‖ = √(2² + 0²) = 2, but along the U it is t_D − t_A = 8. The two ends look close in ℝ² and are far apart on the manifold.
  5. PCA can't unroll it. μ = (1, 1.5); centred: (−1, 1.5), (−1, −1.5), (1, −1.5), (1, 1.5). Σ₁₁ = 4/4 = 1, Σ₂₂ = 9/4 = 2.25, Σ₁₂ = (−1.5 + 1.5 − 1.5 + 1.5)/4 = 0, so w₁ = (0, 1), λ₁ = 2.25.
  6. Scores. z = w₁ᵀx̃ = 1.5, −1.5, −1.5, 1.5. A and D get the same z (8 apart on the manifold), B and C too. The order A, B, C, D is lost: a straight line can't follow a bend.

Say it in one sentence: a d-dimensional manifold is a set that looks like flat ℝᵈ in every small patch (its tangent space) even if it bends through ℝᴰ, so straight-line distance is only trustworthy between close neighbours, and a linear method like PCA can merge points that are far apart along the manifold.

② · 20.4.2

The manifold hypothesis

Why should real data be curved and low-dimensional? Tiny 7×7 images make the case: random pixels are noise, but images made by turning one knob trace a curve through ℝ⁴⁹.

A blurry dot sliding along 4 pixels

Images are 1×4 strips (D = 4). A blurry dot sits at position 1, 2, 3 or 4: a₁ = (1, .5, 0, 0) a₂ = (.5, 1, .5, 0) a₃ = (0, .5, 1, .5) a₄ = (0, 0, .5, 1).

  1. One knob. Every image is fixed by one number, the dot's position, so the images lie on a 1-D manifold in ℝ⁴ (d = 1 ≪ D = 4).
  2. Neighbours are close. ‖a₁ − a₂‖² = .25 + .25 + .25 + 0 = .75 → 0.87; ‖a₂ − a₃‖² = 4 · .25 = 1 → 1.0.
  3. Far ones stop getting farther. ‖a₁ − a₃‖² = 1 + 0 + 1 + .25 = 2.25 → 1.5; ‖a₁ − a₄‖² = 1 + .25 + .25 + 1 = 2.5 → 1.58. Three steps apart is barely farther than two: once the images stop overlapping, pixel distance saturates. Again, only local distances mean anything.
  4. Random images are not on it. Pick 4 random brightnesses, e.g. (.9, .1, .8, .2): no dot position produces that. With binary 28×28 images there are 2⁷⁸⁴ ≈ 10²³⁶ possible pictures, and almost none look like a digit.
  5. Counting knobs for real data. Take one MNIST "6" and rotate it (1 knob) and shift it left/right and up/down (2 more): the copies form a d = 3 manifold inside ℝ⁷⁸⁴.

Say it in one sentence: the manifold hypothesis says natural high-dimensional data (images, sounds) are not spread through ℝᴰ but sit on or near a low-dimensional manifold, because a few underlying factors (pose, position, lighting) generate them; random points in ℝᴰ look like noise.

Graph, then distances, then embedding, by hand

(a) Build the graph, and watch it short-circuit

  1. Same U as ①: A = (0, 3) B = (0, 0) C = (2, 0) D = (2, 3). Pairwise: AB = 3, BC = 2, CD = 3, AD = 2, AC = BD = √13 ≈ 3.61.
  2. k = 1. A's nearest is D (2 < 3), B's is C, C's is B, D's is A. Edges A–D and B–C: two pieces, so some graph distances are ∞.
  3. k = 2. Adds A–B and C–D: a 4-cycle. Shortest A → D is now the edge itself, 2, instead of the true 8. A–D is a shortcut across the gap of the U.
  4. Fix: sample densely. Put a point every 1 unit along the U and connect points within ε = 1. Now A–D (2 apart) is not an edge, and the shortest path A → D walks the whole U: 8. The gap must be wider than the neighbourhood size.

(b) Classical MDS from the graph distances

  1. Correct path distances (from t = 0, 3, 5, 8): AB 3, AC 5, AD 8, BC 2, BD 5, CD 3. Square them: D⁽²⁾ = [0 9 25 64 ; 9 0 4 25 ; 25 4 0 9 ; 64 25 9 0].
  2. Row means 24.5, 9.5, 9.5, 24.5, grand mean 17.
  3. Double-centre: B_ij = −½ (D⁽²⁾_ij − row_i − row_j + grand). B_AA = −½(0 − 24.5 − 24.5 + 17) = 16, B_AB = −½(9 − 24.5 − 9.5 + 17) = 4, B_AD = −½(64 − 24.5 − 24.5 + 17) = −16, B_BB = 1, B_BC = −1.
  4. Notice B = z zᵀ with z = (−4, −1, 1, 4): rank 1, λ₁ = ‖z‖² = 16 + 1 + 1 + 16 = 34, u₁ = z / √34.
  5. Embedding z = √λ₁ u₁ = (−4, −1, 1, 4) = t − 4: the U is unrolled, A and D are 8 apart again. Compare PCA in ①, which put A and D on top of each other.
  6. Feed MDS the shortcut distances from (a) instead and A, D come out close again: the embedding is only as good as the graph.

Say it in one sentence: parametric methods learn a map z = f(x) that works on new points, nonparametric ones only embed the training set, and most of the latter build a k-NN (or ε) graph, compute some property of it (shortest paths, local weights, neighbour probabilities) and find low-dimensional z that keep it, which works only if k or ε is small enough not to short-circuit the manifold.

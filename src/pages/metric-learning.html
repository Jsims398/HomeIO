Learn a ruler where close means "same kind"

Nearest-neighbour methods are only as good as their distance. In raw pixels, two photos of the same face can be far apart while two different faces sit close together. Deep metric learning trains a network so that plain Euclidean distance between its outputs means "these are the same kind of thing".

16.2.2

Deep metric learning

The idea · learn the map, keep the ruler
d(x, x′) = ‖ f(x) − f(x′) ‖₂

A neural net f sends each input to an embedding e = f(x). The distance itself stays boring (Euclidean). All the learning goes into f, and then nearest neighbours, clustering and search work directly on e.

Normalize onto the sphere
‖e‖ = 1  ⇒  ‖e − e′‖² = 2 − 2 eᵀe′

Embeddings are usually scaled to length 1. Then squared distance and cosine similarity say the same thing, and no point can look far away just by having a big norm. In 2-D the "sphere" is a circle, which is what the lab shows.

Why not just classify?
A distance works on classes it never saw

Face unlock, product search, signature checks: new people and products show up after training. A learned distance can compare any two inputs. A fixed C-way classifier only knows its C labels.

Exam notes · 4-point version

Why normalize embeddings: 4 points

The network outputs (before normalizing): f(A) = (3, 4) f(B) = (8, 6) f(C) = (0, −2) f(D) = (−5, 0). A and B are the same kind (say, the same person); C and D are different.

  1. Raw distances. ‖f(A) − f(B)‖ = √(25 + 4) = 5.39, ‖f(A) − f(C)‖ = √(9 + 36) = 6.71, ‖f(A) − f(D)‖ = 8.94. B is only a little closer than C, because B has a big norm (10) and sits far out.
  2. Normalize to length 1. Divide each by its length: e_A = (0.6, 0.8) e_B = (0.8, 0.6) e_C = (0, −1) e_D = (−1, 0).
  3. Cosine similarity e_Aᵀe_B = 0.48 + 0.48 = 0.96, e_Aᵀe_C = −0.8, e_Aᵀe_D = −0.6.
  4. Squared distance from the shortcut ‖e − e′‖² = 2 − 2eᵀe′: A–B 2 − 1.92 = 0.08, A–C 2 + 1.6 = 3.6, A–D 2 + 1.2 = 3.2. (Direct check A–B: 0.2² + 0.2² = 0.08.)
  5. Result. A's nearest neighbour is clearly B (0.08 vs 3.2+). On the circle only the direction counts, so length can't fake "far away".

Say it in one sentence: metric learning trains the network f, keeps the plain Euclidean ruler, and normalizes outputs to the unit sphere so that distance and cosine similarity agree (‖e − e′‖² = 2 − 2eᵀe′).

Exam notes · 4-point version

The lab's score: is a same-class pair closer than a different-class pair?

1-D inputs, two classes interleaved: a₁ = 0 b₁ = 1 a₂ = 2 b₂ = 3 (a = class a, b = class b).

  1. List the pairs. 4 points give 4·3/2 = 6 pairs. Same class: d(a₁, a₂) = 2, d(b₁, b₂) = 2. Different class: d(a₁, b₁) = 1, d(a₁, b₂) = 3, d(a₂, b₁) = 1, d(a₂, b₂) = 1.
  2. Compare every same pair with every different pair: 2 × 4 = 8 comparisons. A same-pair distance (2) is smaller only than the 3. So 2 wins out of 8 = 25%. Below 50%: in input space, distance actively misleads. (1-NN of a₁ is b₁: wrong class.)
  3. After learning an embedding f puts a₁ → 0, a₂ → 0.2 and b₁ → 3, b₂ → 3.1. Same pairs: 0.2, 0.1. Different pairs: 3, 3.1, 2.8, 2.9.
  4. Score again: every same pair beats every different pair, 8 / 8 = 100%. Now nearest neighbour gets every point right.

Say it in one sentence: a good embedding makes every same-class distance smaller than every different-class distance; the lab's percentage is the fraction of (same, different) pair comparisons where that holds, with 50% meaning distance says nothing about class.

16.2.3

Classification losses: let a classifier do it

The recipe
Train a C-way classifier, keep its hidden layer

If the training data has class labels, fit an ordinary softmax classifier: O(N·C) work per pass, with no pairs or triplets to sample. Then drop the output layer and use the normalized penultimate features as the embedding.

Proxy view
logitc = s · eᵀwc,  ‖wc‖ = 1

Normalize the class weights too and each wc becomes a point on the sphere: one stand-in ("proxy") for the whole class. Softmax pulls every embedding toward its own proxy and away from the rest. The scale s sets how sharp the softmax is.

Common extension · margins
logity = s (cos θy − m)

Make the true class win by a margin m in cosine (the CosFace / ArcFace family). Confidence gets harder to earn, so each class is squeezed into a tighter cluster with bigger gaps between classes, which is exactly what nearest-neighbour search wants.

Exam notes · 4-point version

Softmax with 4 class proxies

4 classes with unit proxies on the circle: w₁ = (1, 0) w₂ = (0, 1) w₃ = (−1, 0) w₄ = (0, −1). One embedding e = (0.8, 0.6) whose true class is 1. Scale s = 4.

  1. Cosines cos θ_c = eᵀw_c: 0.8, 0.6, −0.8, −0.6.
  2. Logits s · cos θ_c = 3.2, 2.4, −3.2, −2.4.
  3. Softmax p = e^logit / Σ e^logit → p = 0.687, 0.309, 0.001, 0.003. Loss −ln 0.687 = 0.37.
  4. Add a margin m = 0.2 to the true class only: logit₁ = 4(0.8 − 0.2) = 2.4, now tied with class 2 → p₁ = 0.497. Same e, less confidence: to win again, e has to move closer to w₁.
  5. Why it's metric learning. The gradient pulls e toward its proxy w₁ and away from the others, so same-class embeddings bunch up around one point on the circle. Cost per example: one pass over C = 4 classes, no pairs or triplets.

Say it in one sentence: train an ordinary softmax classifier with normalized embeddings and normalized class weights, so each class weight is a proxy on the sphere; a cosine margin m forces each class into a tighter cluster, and the penultimate layer becomes the embedding.

Exam notes · 4-point version

The confident zone at 4 angles

Same 4 proxies and s = 4. Put e at 4 angles from the true proxy w₁: θ = 0°, 20°, 40°, 60° (toward w₂).

  1. θ = 0°: cosines 1, 0, −1, 0 → p₁ = 0.96. With margin 0.2: 0.92.
  2. θ = 20°: cosines 0.94, 0.34, −0.94, −0.34 → p₁ = 0.91. With margin: 0.82.
  3. θ = 40°: cosines 0.77, 0.64, −0.77, −0.64 → p₁ = 0.62. With margin: 0.42.
  4. θ = 60°: now closer to w₂, p₁ = 0.19. With margin: 0.09.
  5. Read it off. Without margin the "p > 90%" zone reaches past 20°; with m = 0.2 even 20° fails (0.82). The margin shrinks the confident zone, so embeddings must sit closer to their proxy.

Say it in one sentence: the confident zone is the arc around a proxy where p(true class) > 90%; raising the margin m shrinks that arc, which squeezes each class tighter on the circle.

16.2.4

Ranking losses: learn from comparisons

Pairwise · contrastive (Siamese)
𝟙[same]·d² + 𝟙[diff]·[m − d]₊²

Feed two inputs through the same network. Same label: pull together. Different label: push apart, but only until they are m apart. Past that the loss is 0 and the pair is left alone.

Triplet
[ d(a,p)² − d(a,n)² + m ]₊

Only the order matters: the positive p must be closer to the anchor a than the negative n is, with room to spare (m). Clusters can be any size as long as that ordering holds.

N-pairs
log(1 + Σk exp(eᵀek − eᵀe⁺))

One positive against N − 1 negatives at once. It is softmax cross-entropy where the positive is the right answer, so each update gets many comparisons instead of one.

The catch: with N points there are O(N²) pairs and O(N³) triplets, and most of them are already easy (loss 0). Picking useful ones (mining) matters a lot, which the widget below makes visible.

Exam notes · 4-point version

Contrastive and triplet loss on 4 points

Embeddings: anchor a = (0, 0), positive p = (2, 0) (same class), negatives n₁ = (1, 1) and n₂ = (0, 3). Margin m = 2.

  1. Squared distances from a. d(a,p)² = 4 d(a,n₁)² = 2 d(a,n₂)² = 9. n₁ is closer than the positive: a problem.
  2. Contrastive 𝟙[same]·d² + 𝟙[diff]·[m − d]₊². Pair (a, p): 4 (pull together). Pair (a, n₁): [2 − 1.41]₊² = 0.34 (push apart). Pair (a, n₂): [2 − 3]₊² = 0 (already far enough, ignored).
  3. Triplet [d(a,p)² − d(a,n)² + m]₊. With n₁: 4 − 2 + 2 = 4. With n₂: 4 − 9 + 2 = −3 → 0.
  4. Mining. n₁ is a hard negative (closer than p): big loss, useful. n₂ is easy (loss 0): wasted compute. A semi-hard one is farther than p but still inside the margin (loss between 0 and m).
  5. Why mining matters. Even 4 points give 6 pairs and 4 × 3 × 2 = 24 ordered (a, p, n) triples; the counts grow like N² and N³, and most are easy like n₂.

Say it in one sentence: contrastive loss pulls same-class pairs together and pushes different-class pairs apart until they are m away; triplet loss only asks that the positive be closer than the negative by a margin, and since most pairs and triplets give zero loss you must mine the hard ones.

Exam notes · 4-point version

One SGD step on a triplet

Same 4 points: a = (0, 0) p = (2, 0) n₁ = (1, 1) n₂ = (0, 3), m = 2, learning rate η = 0.1. Loss for (a, p, n₁) is L = ‖a − p‖² − ‖a − n₁‖² + 2 = 4.

  1. Negative gradients (the arrows in the widget). −∂L/∂p = 2(a − p) = (−4, 0): p moves toward a. −∂L/∂n = 2(n − a) = (2, 2): n moves away from a. −∂L/∂a = 2(p − n) = (2, −2): a moves toward p and away from n.
  2. Step new = old + η·(−gradient): a → (0.2, −0.2) p → (1.6, 0) n₁ → (1.2, 1.2).
  3. New loss: d(a,p)² = 1.4² + 0.2² = 2.0, d(a,n₁)² = 1.0² + 1.4² = 2.96 → L = 2.0 − 2.96 + 2 = 1.04 (down from 4). n₁ is now semi-hard: farther than p, still inside the margin.
  4. Easy negative. For n₂ the loss is 0, so its gradient is 0: no arrow, no movement.

Say it in one sentence: the triplet gradient pulls the positive toward the anchor and pushes the negative away, but only while the triplet violates the margin; once it is satisfied the gradient is zero.

Exam notes · 4-point version

N-pairs with 1 positive and 3 negatives

Similarity s·cos(angle to anchor) with s = 4. Positive at 30°; negatives at 60°, 120°, 180°.

  1. Similarities 4cos 30° = 3.46 (positive), 4cos 60° = 2, 4cos 120° = −2, 4cos 180° = −4.
  2. Each negative vs the positive exp(sₖ − s⁺): e^(−1.46) = 0.231, e^(−5.46) = 0.004, e^(−7.46) = 0.001.
  3. Loss log(1 + 0.231 + 0.004 + 0.001) = log 1.236 = 0.212.
  4. As a softmax over all 4: positive 0.81, negatives 0.19, 0.003, 0.0005. The loss is −ln 0.81: cross-entropy with the positive as the right answer.
  5. Who gets pushed? Each negative's gradient is proportional to its softmax share, so the 60° negative (0.19) takes nearly all the push; the far ones barely move. With "negative 1 only" the loss is log 1.231 = 0.208: one N-pairs update covers 3 comparisons instead of 1.

Say it in one sentence: N-pairs loss is softmax cross-entropy where the positive must win against N − 1 negatives at once, so every update compares against many negatives and pushes hardest on the most similar ones.

Learn a ruler where close means "same kind"

Nearest-neighbour methods are only as good as their distance. In raw pixels, two photos of the same face can be far apart while two different faces sit close together. Deep metric learning trains a network so that plain Euclidean distance between its outputs means "these are the same kind of thing".

16.2.2

Deep metric learning

The idea · learn the map, keep the ruler
d(x, x′) = ‖ f(x) − f(x′) ‖₂

A neural net f sends each input to an embedding e = f(x). The distance itself stays boring (Euclidean). All the learning goes into f, and then nearest neighbours, clustering and search work directly on e.

Normalize onto the sphere
‖e‖ = 1  ⇒  ‖e − e′‖² = 2 − 2 eᵀe′

Embeddings are usually scaled to length 1. Then squared distance and cosine similarity say the same thing, and no point can look far away just by having a big norm. In 2-D the "sphere" is a circle, which is what the lab shows.

Why not just classify?
A distance works on classes it never saw

Face unlock, product search, signature checks: new people and products show up after training. A learned distance can compare any two inputs. A fixed C-way classifier only knows its C labels.

16.2.3

Classification losses: let a classifier do it

The recipe
Train a C-way classifier, keep its hidden layer

If the training data has class labels, fit an ordinary softmax classifier: O(N·C) work per pass, with no pairs or triplets to sample. Then drop the output layer and use the normalized penultimate features as the embedding.

Proxy view
logitc = s · eᵀwc,  ‖wc‖ = 1

Normalize the class weights too and each wc becomes a point on the sphere: one stand-in ("proxy") for the whole class. Softmax pulls every embedding toward its own proxy and away from the rest. The scale s sets how sharp the softmax is.

Common extension · margins
logity = s (cos θy − m)

Make the true class win by a margin m in cosine (the CosFace / ArcFace family). Confidence gets harder to earn, so each class is squeezed into a tighter cluster with bigger gaps between classes, which is exactly what nearest-neighbour search wants.

16.2.4

Ranking losses: learn from comparisons

Pairwise · contrastive (Siamese)
𝟙[same]·d² + 𝟙[diff]·[m − d]₊²

Feed two inputs through the same network. Same label: pull together. Different label: push apart, but only until they are m apart. Past that the loss is 0 and the pair is left alone.

Triplet
[ d(a,p)² − d(a,n)² + m ]₊

Only the order matters: the positive p must be closer to the anchor a than the negative n is, with room to spare (m). Clusters can be any size as long as that ordering holds.

N-pairs
log(1 + Σk exp(eᵀek − eᵀe⁺))

One positive against N − 1 negatives at once. It is softmax cross-entropy where the positive is the right answer, so each update gets many comparisons instead of one.

The catch: with N points there are O(N²) pairs and O(N³) triplets, and most of them are already easy (loss 0). Picking useful ones (mining) matters a lot, which the widget below makes visible.

Topic 15 Murphy, PML — §18.1 Classification and regression trees

A tree is a stack of yes/no questions

A CART tree asks "is xj ≤ t?" at each node and sends a point left or right until it reaches a leaf, which holds a prediction. Building one comes down to a single step, repeated: take the points at a node, call them D, and pick the feature j and threshold t that cut D into a left part DL and a right part DR that are as pure as possible. For classification, purity is usually measured with the Gini index.

① Compute DL, DR and Gini for one split ② Repeat it to grow the tree
①

One split: DL, DR and the Gini index

Step 1 · split the data
DL = {n : xnj ≤ t},  DR = {n : xnj > t}

Pick a feature j and a threshold t. Every point with xj ≤ t goes left, the rest go right. Only thresholds between two neighbouring data values matter, so the candidates Tj come from sorting the unique values of xj.

Step 2 · score each side
π̂c = Nc / |D|,  G = Σc π̂c(1 − π̂c) = 1 − Σc π̂c²

π̂c is the fraction of the node's points in class c. Gini is the chance that two points drawn at random from the node (with replacement) have different labels. A pure node has G = 0; three equal classes give G = 2/3.

Step 3 · weigh and pick
cost = |DL|/|D| · G(DL) + |DR|/|D| · G(DR)

Each side counts in proportion to how many points it holds. Try every j and every t ∈ Tj, and keep the (j, t) with the lowest cost.

Try this
  1. Slide t slowly. The cost only changes when a point crosses the line, so the curve is flat steps. That is why only the candidates Tj need checking.
  2. Push t all the way to 0 or 10. One side is empty and the cost equals G(D): an "empty" split buys nothing.
  3. Find a t that makes DL pure (G = 0). Is it the best split? Often not, if it only peels off a few points.
  4. Switch to Error rate and slide again. The curve has long flat stretches where Gini and entropy still slope downhill toward the good splits.
  5. Click points near the cut to change their class and watch π̂ and G update.
Why weight by |DL|/|D|?

Without the weights, cutting off one point would give a perfectly pure child (G = 0) and look great. Weighting by size makes the cost the average impurity per point after the split, so a child counts only as much as the points it holds.

And for regression trees?

Same DL / DR search and the same weighted cost, but the impurity of a node is the mean squared error around its average: c(D) = (1/|D|) Σn∈D (yn − ȳ)². A leaf predicts ȳ, the mean of its points.

②

Grow the tree: repeat the split on DL and DR

The tree is grown greedily. Find the best split of the root, then treat DL and DR each as a new D and do it again. A node stops splitting when it is pure, reaches the maximum depth, or every split would leave a child below the minimum size.   4. Now raise the minimum points per leaf. Those tiny boxes disappear and the tree gets simpler, at the cost of a little training error.
Why greedy, one node at a time?

Finding the best tree overall is NP-complete, so CART does not try. It makes the locally best split at each node and never goes back. That is fast (sort each feature, scan the thresholds), but a split that looks poor now and would set up great splits later is never chosen.

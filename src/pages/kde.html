Topic 11 Murphy, PML — §16.3 Kernel density estimation · Kernel regression

Put a little hill on every data point

Say you measured 20 people's heights. What does the curve for everyone's height look like? Kernel density estimation (KDE) answers with one simple trick: put a small smooth bump on each measurement and add the bumps up. The result is a smooth curve that tells you which values are likely, and you can even use it to make brand-new, realistic data.

16.3.1

Density kernels: one little bump

Big idea
A kernel is a tiny probability bump you can put anywhere

It is the building block for everything on this page. It is centred on 0, the same on both sides, and the total area under it is exactly 1.

Picture it
Exactly one cup of sand

Pour one cup of sand on a table. You can make a tall, narrow pile or a low, wide one, but it is always one cup. The bandwidth h is how wide you spread it.

Formula, decoded
Kh(x) = 1⁄h · K(x ⁄ h)

x ⁄ h stretches the bump sideways by h. 1⁄h squashes it down by the same amount, so the area stays 1. The rules: ∫K = 1 (one cup), K(−x) = K(x) (symmetric), K ≥ 0.

Why must the area be exactly 1?

A probability curve's total area is the chance that something happens, which must be 100%. If each bump has area 1 and we average N bumps, the result also has area 1, so it is a real probability distribution.

16.3.2

Parzen window: stack the bumps

Big idea
Put one kernel on every data point, then average them

No training, no formula for the shape. The data is the model. That is why the book calls KDE a non-parametric method: it keeps all N points instead of a few numbers like a mean and variance.

Picture it
Each point pours 1 ⁄ N cup of sand

Where points crowd together the piles overlap and build a hill. Where there are no points the table stays flat. The height of the sand at any spot is how likely a new value there is.

Formula, decoded
p̂(x) = 1⁄N Σn Kh(x − xn)

xn is data point number n. x − xn is how far x is from it. Kh(…) is that point's bump height at x. Σ adds every point's bump, and 1⁄N gives each one an equal share.

16.3.2

Lab: build the curve, then make new data

How to sample from p̂(x)
Pick a point, then nudge it

1. Choose one of the N data points at random (each has a 1 ⁄ N chance). 2. Add a random nudge drawn from the kernel. That is all. It works because p̂ is just N equal bumps mixed together, so picking a bump and then drawing from it is the same as drawing from p̂.

Watch out
Small h ⇒ near-copies

The nudge is about h in size. If h is tiny, every "new" point is almost exactly an old one, so the model just memorizes its data. If h is huge, new points can land where real data never goes.

Click the number line to add a data point; click an existing point to remove it. Then press Generate 1 a few times and read the steps, or Generate 100 to fill a histogram.

Why is the cluster taller?

Every point adds the same amount of sand. Three bumps overlapping in one spot pile up to about three times the height of a lone bump. Many data points nearby means that value is common, so it should be more likely.

16.3.3

How to choose the bandwidth h

Big idea · Goldilocks
Too small is spiky, too big is blurry

h is the one knob KDE has, like the focus ring on a camera. Small h shows every grain of noise; big h smears real features away. We want the setting that would best predict data we haven't seen.

Option 1 · rule of thumb
h = σ̂ · (4 ⁄ 3N)1/5

σ̂ is how spread out the data is (the book uses a robust version: 1.4826 × the median distance from the median). More spread ⇒ wider h. More data ⇒ smaller h, but slowly: 32× more data only halves h. It assumes one bell-shaped hump, so it oversmooths two-hump data.

Option 2 · cross-validation
Hide a point, see if the curve expected it

For each point: build p̂ from all the other points and check how high the curve is at the hidden one (we use the log). Average over all points. Pick the h with the best score. Hiding matters: without it, a tiny h would cheat by putting a spike exactly on every point.

The dashed curve is the true distribution (normally we never get to see it). We drew {{ bwN }} points from it, shown as ticks along the bottom. Move h and see how well the estimate recovers the truth.

Why does more data allow a smaller h?

With more points, neighbours are closer together, so even narrow bumps overlap into a smooth curve. Narrower bumps can then show finer detail without becoming spiky.

16.3.4

From KDE to KNN classification

Big idea
Don't fix the window size. Grow a balloon until it holds K points

KDE with a fixed window can come up empty in sparse areas. Flip it around: fix how many points you want (K) and let the radius stretch. The colours inside the balloon tell you the class. That's K-nearest neighbours (§16.1), rebuilt from density estimation.

Picture it
Polling your neighbours

You want to guess which team a neighbourhood supports, so you ask the 5 nearest people. Downtown you only walk half a block to find 5; in the countryside you might walk a mile. Same number of answers, different distances.

Formula, decoded
p(y = c | x) = Nc(x) ⁄ K

Density ≈ K ⁄ (N·V), where V is the balloon's area. For class c: p(x | c) ≈ Nc(x) ⁄ (Nc·V) and p(c) = Nc ⁄ N. Put them in Bayes' rule and V cancels: the answer is just the fraction of the balloon that is colour c.

So which K is best?

Same Goldilocks story as h in 16.3.3. Small K overfits (follows every single point), big K underfits (washes out small groups). In practice you pick K with cross-validation too.

16.3.5

Kernel regression: predicting numbers

Big idea · 16.3.5.1
Predict y with a weighted average of nearby y's

Closer points get bigger weights, and the kernel decides how much bigger. Picture guessing the temperature at your house from nearby weather stations: you trust the closest stations the most.

Formula, decoded · Nadaraya–Watson
ŷ(x) = Σn wn(x) · yn

wn(x) = Kh(x − xn) ⁄ Σn′ Kh(x − xn′). Each weight is a bump height, divided by the total so all the weights add up to 1, like percentages. It falls out of KDE: build a KDE of the (x, y) pairs and ask "what's the average y at this x?"

How sure are we? · 16.3.5.2
𝕍[y | x] = σ² + Σn wn yn² − ŷ²

The second part is the weighted spread of the neighbours' heights: big when nearby points disagree. σ² is the width of each point's bump in the y direction. The shaded band in the lab is ŷ ± 2 standard deviations.

Upgrade · 16.3.5.3
Locally weighted regression: fit a tiny line

Instead of averaging the nearby heights (a flat guess), fit a straight line through the nearby points, with closer points counting more, and read the line at x. It fixes the edge problem: at the end of the data all neighbours sit on one side, and a line can follow the trend where an average can't.

Why does the average miss at the edge?

At x = 0 there is no data to the left, so every neighbour is to the right. Here the curve is rising, so those neighbours are all higher than the true value, and their average comes out too high. A line through them knows the curve is rising and can follow it back down to x = 0.

SectionIn one sentenceThe knob

16.3.2 Parzen / KDEAverage one bump per data point to get a smooth density, and sample new data by "pick a point, then nudge it".h

The catch: all of these keep every training point and compare against all of them for each new prediction, so they get slow with huge datasets. They also struggle in many dimensions, where "nearby" points become rare (the curse of dimensionality from §16.1).
